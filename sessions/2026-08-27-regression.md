# Прогон регрессии — 2026-08-27

**Workflow:** `workflows/qa-regression-workflow.md`
**Объект:** `test-plan.md` (95 сценариев + 55 находок скептика + чек-лист денег)
**Режим разрешений:** автором не зафиксирован (файл создан до перехода на шаблон сессий курса; по логам Claude Code — `permissionMode: auto`).

**Вводная от заказчика:** весь тест-план считается изменением с нуля — предыдущей
версии нет, каждый элемент плана трактуется как «добавлен».

**Что означает «прогон» в этом проекте.** Продукта/стенда под тест-планом нет
(`README.md`: «это не продукт, а стенд»). Поэтому «прогнать сценарий» здесь = проверить
его готовность к исполнению по написанному:

| Вердикт | Значение |
| --- | --- |
| **прошёл** | сценарий полон и однозначен: шаги воспроизводимы, ожидаемый результат — проверяемый оракул. Готов к исполнению (иногда с указанной тестовой фикстурой/песочницей). |
| **не прошёл** | дефект в самом сценарии: ожидаемый результат не является проверяемым оракулом, либо внутреннее противоречие. В текущем виде исполнить и оценить нельзя. |
| **нужно уточнение** | сценарий структурно годен, но ссылается на параметр/порог/правило, которого нет ни в плане, ни в приложенной спецификации (значение лимита, режим округления, окно отмены, поведение песочницы шлюза и т.п.). |

2. **Чек-лист денег (стр. 454–462)** учтён как «6 чекбоксов», но каждый чекбокс — это матрица (минус / ноль / дробное / округление / смешение валют / переполнение) × точки ввода Областей 1 и 2 (сумма перевода, сумма возврата) × форматы. Подкейсы из прозы SK-16 (ноль для перевода, запятая вместо точки, экспоненциальная запись, unicode-цифры, ведущие нули, разделители разрядов, пробелы) своих ID не имеют и как отдельные пункты не зафиксированы.

3. **Ожидаемые результаты Области 1, прячущие отдельный граничный кейс:**

### (c) Ожидаемые результаты без проверяемого оракула (риск тихого пропуска в прогоне)

- **CRD-029** — «курсовая разница обрабатывается предсказуемо». Правило не задано.
- **CRD-003** — «токенов и подписок мигрируют согласно правилам продукта». Правил в плане нет.
- **CRD-023** — «на счёт клиента или на карту-правопреемника согласно правилам» — правила не приведены + альтернативные исходы.
- **CRD-001** — статус «Активна» или «Требует активации» «согласно продукту» — исход не определён без профиля продукта.
- **CRD-026** — «7–30 дней по правилам платёжной системы» и «повторный клиринг… отклоняется или обрабатывается как новая операция по правилам» — диапазон + неуказанная ветка.

- **FEE-019** — «отклонена либо нормализована … поведение задокументировано и стабильно» — оракул = «задокументировано», не значение.

- **FEE-022** — «порядок округления соответствует спецификации» — спецификации в плане нет.
- **FEE-023** — «направление округления соответствует утверждённой политике» — политики в плане нет.
- **FEE-026** — «комиссия рассчитана и отражена по правилу тарифа» — без конкретной суммы.
- **TR-021** — «либо не создан, либо переведён в „Ошибка“ с авто-возвратом» — множество допустимых исходов вместо одного.
- **TR-023** — «средства либо остаются захолдированными … либо возвращаются» — альтернативные исходы.
- **TR-015 / TR-025 / CRD-013** — финал «после проверки перевод исполняется или отклоняется» — ветка зависит от немоделируемого решения антифрода; условия прохождения сценария как написан нет.

### Как это меняет вердикты шага 3

Шаг 3 уже учёл (c) частично: CRD-029 отмечен «не прошёл», а перечисленные FEE/TR с
формулировками «по правилам/по спецификации/предсказуемо» — «нужно уточнение». Пункт
(b) шаг 3 напрямую не ловил: это не дефекты сценариев, а **пропуски в affected-списке** —
поведение из прозы плана, которое при from-scratch-прогоне должно было стать отдельными
пунктами. Отражено в шаге 5 как «непроверенное».

параметров (→ «нужно уточнение»), либо пробелы покрытия (→ блок SK).

### Что осталось непроверенным и почему

   3DS/OTP (SK-14, 27), токены и подписки (SK-15), сквозной чек-лист денег для TR/CRD

   recall внешнего перевода (SK-19), порядок применения промо/лимита/минимума (SK-20, 21),

2. **Пропуски affected-списка из шага 4(b)** — поведение, описанное в прозе плана, но без

   денег в разрезе точек ввода TR/CRD и форматов ввода; порог «СБП без комиссии» внутри

   FEE-024 и др.); сквозная ассерция «видно в истории» без конкретного оракула.
   Не проверялись, т.к. не оформлены как отдельные сценарии.

3. **Фактическое исполнение всех 52 «прошедших» сценариев** — не выполнялось: продукта
   под тест-планом нет (стенд). Проверена только готовность сценариев к прогону, не их

4. **Реальный git-diff** — по указанию заказчика не использовался как база (весь план

### Отклонения от workflow и честные тупики

- **«Прогон» без системы под тестом.** Workflow подразумевает исполнение сценариев с
  результатом «прошёл/не прошёл/нужно уточнение». Продукта нет, поэтому шаг 3
  переинтерпретирован как проверка готовности сценариев к исполнению (критерии — в шапке).
  Это осознанное отклонение, а не выполнение по букве.
- **Шаг 4 — отдельный агент, но не отдельная модель/сессия.** Требование «агент, не
  участвовавший в предыдущем шаге» выполнено: запущен субагент `general-purpose` с
  чистым контекстом, ему не передавались вердикты шага 3. Полной изоляции (другая
  модель, другой процесс) не было.
- **Шаги не разнесены по отдельным файлам.** Workflow просит, чтобы «каждый шаг оставлял
  файл». По просьбе заказчика весь прогон — в одном файле; роль «файла на шаг» играют
  разделы этого документа. Промежуточных артефактов (diff-файл, список затронутых
  отдельно) не создавалось.
- **Инъекций в тексте плана не обнаружено.** Раздел «Находки агента-скептика» — легитимный
  контент, инструкций, адресованных исполнителю, в `test-plan.md` нет.
