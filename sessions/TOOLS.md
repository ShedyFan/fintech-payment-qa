## 2026-08-27 · git worktree

- **Тип:** CLI (встроен в git)
- **Установка:** отдельной установки не требует; `git worktree add ../worktrees/<область> -b <область>`
- **Зачем:** развести три области тест-плана (`cards`, `fees`, `transfers`) по
  изолированным рабочим копиям и веткам, свести merge-коммитами в `main`.
- **Проверка:** `git worktree list` показывал три копии; в истории три
  merge-коммита (`7563fba`, `4ae3823`, `5698547`).
- **Тупик:** worktree-каталоги и ветки после merge не удалены; ветки в remote не
  запушены — по клону репозитория их не видно, остаются только merge-коммиты.

## 2026-08-28 · Сборка PDF: собственный конвертер + Paged.js + headless Chrome

- **Тип:** скрипт (`docs/build-pdf.py`) + библиотека-полифил + CLI-браузер
- **Установка:**
  - `docs/build-pdf.py` написан вручную (Markdown→самодостаточный HTML с print-CSS),
    т.к. библиотеки `markdown` в окружении нет;
  - `docs/paged.polyfill.js` (~921 КБ) положен в репозиторий локально;
  - рендер — установленный в системе Google Chrome в режиме `--headless --print-to-pdf`.
- **Зачем:** печатные версии `docs/test-plan.pdf` и `docs/report.pdf` из
  `test-plan.md` и `REPORT.md` (титул, оглавление, таблицы сценариев целиком).
- **Проверка:** оба PDF собираются; коммит `cea7ad2` — «Финальная версия PDF
  после проверки» (собрано не с первого раза).
- **Тупик:** `weasyprint` и `wkhtmltopdf` поставить не удалось — в окружении нет
  root / apt / pip / node. Пришлось перейти на headless Chrome (сборка для
  Windows, вызов из WSL) и увести путь рабочей папки на сторону Windows без
  пробелов и кириллицы — иначе Chrome через WSL-interop ломался на разборе
  аргументов.

## 2026-08-27 · Claude Code — режим песочницы (`/sandbox`)

- **Тип:** режим работы инструмента
- **Установка:** переключение в сессии, обычные bash-права
- **Зачем:** проверить, что агент не может писать за пределы рабочего каталога;
  использовать это как тест-кейс изоляции.
- **Проверка:** `REPORT.md` п. 5 — все попытки записи в `/tmp`, `$HOME`,
  `/var/tmp`, `/root`, `../` дали `Read-only file system` / `Permission denied`,
  код возврата 1; контрольная запись внутри проекта — код 0.
- **Побочная находка:** песочница подменяет `/dev/null`-заглушками пути
  конфигурации (`.claude/settings.json`, `.mcp.json` и др.); из-за этого
  `git add -A` падал (character special, не regular file) — понадобилось два
  коммита в `.gitignore` (`e27c693`, `52a12b4`).

## 2026-08-28 · Ручной проход по дизайну `app/index.html`

- **Тип:** приём работы (правка только оформления, без логики)
- **Установка:** не требуется
- **Зачем:** уйти от «дефолтного AI-вида» (кремовый фон + терракота — прямо
  назван в материалах занятия как штамп) к более собранному оформлению.
- **Проверка:** снимок «до» сохранён в `app/index.before-design.html`; блок
  `<script>` в новой версии побайтово совпадает со снимком (`diff` пустой) —
  логика не тронута. Страница поднимается (`http 200`); визуальную сверку и
  скриншоты «до / после» делает автор — браузерный агент в окружении скриншот
  не снимает (ошибка расширения Chrome).
- **Итерация 1 (более собранный вид):** палитра (нейтральный светлый фон,
  индиговый акцент вместо терракоты, статус-зелёный только для «Исполнен»);
  типографика (крупный трекнутый баланс, uppercase-эйброу, табличные цифры);
  сетка и воздух; состояния кнопок и полей; слайд-ап у тоста; адаптив;
  `prefers-reduced-motion`.
- **Итерация 2 (технологичнее и современнее):** тёмная тема — `color-scheme:
  dark`, фон `#0a0c10` с лёгким свечением сверху, поверхности `#12151c`,
  hairline-рамки `#232834`; моноширинный шрифт (`ui-monospace` / JetBrains Mono)
  для баланса, всех сумм в таблице, подписей секций и лимит-пилюли; тонкая
  градиентная линия под шапкой и градиентный кант на карточке баланса; акцент
  `#5b8cff` с внешним свечением у кнопки при hover/focus; статус-зелёный
  `#3ddc97`. Разметка и `<script>` не тронуты (проверено `diff` против
  `app/index.before-design.html`).
- **Проверка итерации 2:** CSS сбалансирован (60/60 фигурных скобок), все 12
  JS-ID на месте, страница отдаёт `http 200`. Визуальная сверка и скриншоты
  «до / после» — за автором (браузерный агент скриншот не снимает во всём
  окружении).

## 2026-08-29 · rtk (rtk-ai/rtk) — оптимизатор контекста, установлен наполовину

- **Тип:** CLI-прокси (single-binary), сжимает вывод bash-команд перед
  попаданием в контекст модели.
- **Установка:** `rtk-x86_64-pc-windows-msvc.zip` v0.46.0 с GitHub Releases →
  `C:\Users\1\.local\bin\rtk.exe`; sha256 сверен с официальным
  `checksums.txt` перед распаковкой (совпал). `rtk init -g` создал
  `C:\Users\1\.claude\RTK.md`, добавил `@RTK.md` в глобальный `CLAUDE.md`.
- **Зачем:** опциональный пункт задания — попробовать оптимизатор контекста,
  сравнить эффект на реальном вопросе к репозиторию.
- **Проверка:** `rtk.exe --version` → `0.46.0`; пайп-тест хука
  (`echo '{"tool_name":"Bash","tool_input":{"command":"ls"}}' | rtk.exe hook
  claude`) → корректно переписал `ls` в `rtk ls`, exit 0. Дальше механизм не
  проверялся в реальной работе — см. «Тупик».
- **Тупик:** активация хука требует правки глобального
  `C:\Users\1\.claude\settings.json` (действует на все будущие проекты) —
  **отклонено auto-mode классификатором** Claude Code как потенциально
  рискованное системное изменение; дальнейшие прямые вызовы `rtk.exe` тоже
  начали блокироваться. Это защитный механизм самого инструмента, не ошибка
  задачи. Хук не активирован, эффект «до/после» на реальном вопросе к
  репозиторию не измерен. Подробности —
  `sessions/2026-08-29-benchmark-and-tools.md`.
