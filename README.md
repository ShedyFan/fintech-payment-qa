# QA: тест-план платёжных сценариев

Домашнее задание №2, курс AICOURSE, направление QA. Тема — вариант A4 из приложения к
заданию: тест-план по платёжным сценариям финтех-продукта (переводы, лимиты, карты,
комиссии, отмена операции).

**Что это не продукт, а стенд.** Смысл работы — не сам тест-план, а то, как он собран:
несколькими параллельными агентами, с независимой проверкой и с попыткой сломать
собственную работу.

## Что сделано

- [ ] Тест-план по трём областям: переводы/лимиты, карты/отмена, комиссии/округление
- [ ] Отдельный агент-скептик, ищущий дыры в готовых чек-листах
- [ ] Workflow — повторяемая процедура прогона проверок
- [ ] Три git worktree — по одному на область, с merge в конце
- [ ] Изоляция агента в песочнице, зафиксирован вывод отказа
- [ ] Проверка на скрытую инструкцию (инъекцию) двумя моделями
- [ ] PDF-версия тест-плана и итогового отчёта

*(отмечается по мере выполнения)*

## Структура репозитория

```
.
├── README.md              — этот файл
├── test-plan.md           — сводный тест-план (после сведения трёх областей)
├── test-areas/            — черновики по каждой области до сведения
│   ├── transfers.md       — переводы и лимиты
│   ├── cards.md           — карты и отмена операции
│   └── fees.md            — комиссии, округление, граничные значения
├── workflows/
│   └── qa-regression-workflow.md   — повторяемая процедура прогона проверок
├── sessions/               — журнал сессий (промпты дословно, решения)
├── REPORT.md               — отчёт: что сделано, что не сработало
└── docs/                    — итоговые PDF (появятся на финальном шаге)
```

## Как посмотреть работу

1. Тест-план целиком — `test-plan.md`.
2. Как собирался тест-план — по коммитам и по `sessions/`.
3. Отчёт по всем пунктам задания — `REPORT.md`.
4. Итоговый PDF — `docs/`.

## Почему этот вариант

Взят вариант A4 из приложения к заданию — тест-план платёжных сценариев. Область
понятна без дополнительного контекста, естественно разбивается на независимые части
для параллельных агентов и даёт материал сразу для нескольких плюсовых пунктов
(worktrees по областям, инъекция в тестовых данных).
