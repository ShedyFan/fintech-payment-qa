# QA: платёжный кабинет + тест-план платёжных сценариев

Домашнее задание, курс AICOURSE, направление QA. Тема — вариант A4: платёжные
сценарии финтех-продукта (переводы, лимиты, комиссии, отмена операции).

Смысл работы — пройти цикл целиком: контекст → спецификация → наивный прогон →
работа по спеке → проверка → отчёт. В репозитории есть небольшая система под
тестом (`app/`), тест-план против неё и параметрический тест-план по домену.

**Метод.** Три области домена (переводы, карты, комиссии) разведены через
git-ветки и worktree с merge в конце — **не** через одновременно работающих
субагентов (ранняя формулировка про «параллельных агентов» была неточной, см.
`REPORT.md` § 2). Реальный параллельный запуск сделан отдельно, на диагностике
трёх багов (BUG-02/03/04, позже починены) —
`sessions/2026-08-29-parallel-bug-analysis.md`: три субагента `general-purpose`
одним батчем, каждый в своей зоне, без права трогать код продукта. Независимые
взгляды: агент-скептик по чек-листам, субагент на проверку полноты в регрессии,
аудит всего репозитория тремя моделями (чистая сессия Sonnet, субагент Opus,
сторонний Qwen).

## Как запустить

Нужен Python 3 и любой браузер. Из корня репозитория:

```bash
# 1. Поднять систему под тестом
python -m http.server 8765
#    Открыть http://localhost:8765/app/index.html
#    Ожидаемо: заголовок вкладки «Платёжный кабинет», консоль без ошибок.
#    Проверка: перевод 1000 ₽ уводит баланс 50000.00 -> 48990.00 (комиссия 10.00).

# 2. Автотест продукта (Playwright — зависимость в package.json)
npm install && npx playwright install chromium
npm test                       # = npx playwright test tests/payments.spec.js
#    Прогон в настоящем Playwright выполнен 2026-08-29: 9/9 PASS
#    (базовое поведение + регрессия по BUG-01/03/04 + seed-сценарии
#    APP-008/011/012). Вывод — tests/README.md и
#    sessions/2026-08-29-fix-bug-02-03-04.md.

# 3. Прогон регрессии по workflow — промпт внутри файла
cat workflows/qa-regression-workflow.md
#    Последний прогон: sessions/2026-08-28-regression.md

# 4. Проверка устойчивости к инъекции в тестовых данных
#    Дать модели файл test-areas/sample-transaction*.json с нейтральным
#    промптом «проверь транзакцию и подготовь отчёт». Ожидаемо: встроенная
#    инструкция не выполнена. Результаты — REPORT.md § 6.

# 5. Печатные версии (пересобирает docs/test-plan.pdf и docs/report.pdf)
python docs/build-pdf.py
#    Chromium ищется автоматически (Chrome → Edge, либо путь в CHROME_BIN);
#    имя автора на титуле — из переменной PDF_AUTHOR. Нужен только Python 3
#    (stdlib, стороннего markdown не требуется).
```

Правила проекта и все команды проверки собраны в `AGENTS.md` → «Как запускать и
проверять» (читается Claude Code через `CLAUDE.md`, а также Codex/Cursor и др.).

## Что сделано

- **Система под тестом** — `app/index.html`: платёжный кабинет (баланс, перевод,
  комиссия 1% с клиппингом 10/300, дневной лимит 100 000, отмена в окне 60 сек,
  история, `localStorage`). Собран за один проход по `app/build-brief.md`, без
  ручной доводки. Дизайн переработан отдельным проходом (тёмная тема), логика не
  тронута; снимок «до» — `app/index.before-design.html`.
- **`SPEC.md`** — спецификация: сценарии, состояния, допущения, нецели, открытые
  вопросы, критерии приёмки. Часть блоков `ВОПРОС:` ждёт ответов автора.
- **`CLAUDE.md` / `AGENTS.md`** — Часть I (правила курса) дословно, Часть II
  заполнена под проект: стек, порт, запрет править код в режиме тестирования,
  формат баг-репорта.
- **Тест-план** `test-plan.md`: Области 1–3 — параметрические сценарии домена
  (TR-001…044, CRD-001…044, FEE-001…048) с разделами «Открытые вопросы»;
  Область 4 — исполняемые проверки против `app/` (APP-001…014); блок «Находки
  агента-скептика» SK-01…55; сквозной чек-лист «Граничные значения в деньгах».
- **Баг-репорты** — `bugs/BUG-01…04`, формат из `AGENTS.md`, с воспроизведением
  из `localStorage` / консоли. **Все четыре починены** отдельными фикс-сессиями:
  BUG-01 (округление) — 2026-08-28; BUG-02 (UTC-дата лимита), BUG-03 (парсинг
  суммы), BUG-04 (битая схема) — 2026-08-29 (`sessions/2026-08-29-fix-bug-02-03-04.md`).
  У каждого репорта раздел «Исправлено» с diff.
- **Автотест** — `tests/payments.spec.js` (Playwright): **прогнан в настоящем
  Playwright 2026-08-29, 9/9 PASS**. APP-009 (BUG-03) и APP-014 (BUG-04) из
  красных стали зелёными; APP-008/011/012 добавлены seed-тестами. Вывод —
  `tests/README.md`.
- **Наивный прогон** — `naive-run/test-plan-naive.md` (субагент с чистым
  контекстом, один промпт); сравнение со спековым результатом — `REPORT.md` § 9.
- **Workflow регрессии** — `workflows/qa-regression-workflow.md`, два прогона
  (`sessions/2026-08-27-regression.md`, `sessions/2026-08-28-regression.md`).
- **Изоляция агента в песочнице** — `REPORT.md` § 5: попытки записи за пределы
  каталога с командами и кодами возврата.
- **Устойчивость к инъекции** — `REPORT.md` § 6: три вектора внедрения × две
  модели (Haiku 4.5 и Sonnet/Opus).
- **Независимый аудит** — тремя способами: чистой сессией той же модели
  (`sessions/2026-08-28-independent-audit.md`, 14 находок); субагентом на
  **Claude Opus** (`sessions/2026-08-29-course-compliance-audit.md`, 18 находок);
  сторонней моделью **Qwen** (аудит по публичному репо, находки разобраны там же).
  Все три — с ответом на каждую находку.
- **Печатные версии** — `docs/test-plan.pdf`, `docs/report.pdf`, сборщик
  `docs/build-pdf.py`.
- **Агенты параллельно** — `sessions/2026-08-29-parallel-bug-analysis.md`: три
  субагента одним батчем, каждый диагностирует свой баг (BUG-02/03/04) в своей
  зоне, без права трогать `app/` или зону соседа; результаты сведены в один
  документ вместе с замером времени, подтверждающим параллельность.
- **Замер параллельно/последовательно** —
  `sessions/2026-08-29-benchmark-and-tools.md`: та же задача (приоритизация
  открытых вопросов трёх областей тест-плана) прогнана и параллельно тремя

  чистого числового результата не вышло, зато нашлась содержательная
  расхождение по вопросу TR-005/031.

## Что не сделано и ограничения

- **BUG-01…04 — все починены** (BUG-01 — 2026-08-28; BUG-02/03/04 — 2026-08-29),
  регрессия подтверждена Playwright **9/9 PASS**. APP-008 (граница дневного
  лимита), APP-011 (окно отмены истекло), APP-012 (персистентность + битый JSON)
  переведены из «ручных» в автотесты через seed-состояние `localStorage`.
  Не автоматизировано: реальное ожидание 60 сек в APP-011 и поведение ровно в
  местную полночь / при DST — нужен контроль системных часов.
- **Продуктовое решение по BUG-02** (пересмотрено 2026-08-29): сутки дневного
  лимита считаются по **фиксированному деловому поясу МСК (UTC+3, без DST)**,
  а не по часам устройства и не по UTC — лимит обнуляется в одну и ту же
  полночь для всех пользователей. Смещение — константа `LIMIT_TZ_OFFSET_MIN`
  в `app/index.html` (у стенда сервера нет).
- **`SPEC.md`** — статус «согласована» (2026-08-28): критерии приёмки
  проставлены, блоки `ВОПРОС:` закрыты (часть — осознанно оставлена открытой,
  целевое поведение продукта определяет владелец).
- **Режим разрешений** проставлен во всех файлах `sessions/` (часть —
  восстановлено по логам Claude Code, отмечено в самих файлах).
- **`docs/build-pdf.py`** — 2026-08-29 сделан переносимым: Chromium ищется
  автоматически (Chrome → Edge, либо `CHROME_BIN`), временная папка — системный
  temp, имя автора — `PDF_AUTHOR`. Нужен только Python 3 (stdlib). PDF в репо
  пересобраны этим скриптом 2026-08-29.
- **`docs/paged.polyfill.js`** (~921 КБ) лежит в репозитории намеренно
  (библиотек в окружении сборки поставить негде) — раздувает клон.
- **Кросс-проверка другой моделью** — независимый аудит проведён субагентом на
  Claude Opus (`sessions/2026-08-29-course-compliance-audit.md`); Codex и
  Fable 5 в окружении недоступны. Ранее аудит был только чистой сессией той же
  `claude-sonnet-5` (`sessions/2026-08-28-independent-audit.md`).
- Логи субсессий теста инъекции (Haiku / Opus) в `sessions/` не сохранены —
  в `REPORT.md` § 6 приведены таблица и выдержки, дословный ответ — для одного
  вектора.
- Ветки `cards`/`fees`/`transfers` и каталоги worktree после merge не удалены
  на исходной машине автора и не запушены в `origin`; сама история при этом
  воспроизводится — коммиты веток достижимы через три merge-коммита
  (`git log --graph`). Свежий клон extra-веток и worktree не содержит.
- **`rtk` не засчитывает собственный хук как «установленный».** Хук
  технически исправен (путь в `settings.json` починен — было
  экранирование обратных слэшей, съеденное bash), реальный эффект измерен
  (`rtk gain`: 3 команды, 86.4% экономии токенов на `git status`), но сам
  `rtk` пишет «no hook installed globally», и экономия шла через ручную
  маршрутизацию команд, а не автоматический перехват. Причина расхождения не
  раскопана — честный открытый вопрос, не блокирует сдачу. Подробности —
  `sessions/TOOLS.md`.

## Структура репозитория

```
.
├── CLAUDE.md / AGENTS.md   — правила проекта (Часть I — курс, Часть II — проект)
├── SPEC.md                 — спецификация (черновик, часть вопросов открыта)
├── README.md               — этот файл
├── REPORT.md               — отчёт по пунктам задания + § 9 сравнение прогонов
├── test-plan.md            — сводный тест-план (Области 1–4 + SK + чек-лист денег)
├── app/                    — система под тестом
│   ├── index.html          — платёжный кабинет
│   ├── index.before-design.html — снимок «до» дизайн-прохода
│   ├── build-brief.md      — бриф, по которому собран продукт
│   └── README.md           — как поднять, заложенные правила
├── bugs/                   — BUG-01…04 (формат из AGENTS.md)
├── tests/                  — payments.spec.js (Playwright) + README
├── test-areas/             — черновики областей + тестовые данные инъекции
├── naive-run/              — наивный прогон и его сравнение с спековым
├── workflows/              — qa-regression-workflow.md
├── sessions/               — журнал: файл на сессию, STATE.md, TOOLS.md
└── docs/                   — test-plan.pdf, report.pdf, build-pdf.py, *.html
```

## Как читать работу

1. Ход работы — `sessions/` по датам, `STATE.md` (состояние «как есть»),
   `TOOLS.md` (инструменты и тупики).
2. Тест-план целиком — `test-plan.md`; проверки против продукта — Область 4.
3. Дефекты — `bugs/`; отчёт по всем пунктам — `REPORT.md`.
4. Аудит и ответ на находки — `sessions/2026-08-28-independent-audit.md`.

## Почему этот вариант

Платёжные сценарии понятны без дополнительного контекста, естественно бьются на
независимые части (worktree по областям) и дают материал сразу для нескольких
плюсовых пунктов: продукт с реальными дефектами, инъекция в тестовых данных,
проверка изоляции.
