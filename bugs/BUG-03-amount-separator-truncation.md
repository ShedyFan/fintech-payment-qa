# BUG-03 — Разделитель разрядов в сумме молча обрезает перевод (`1 000` → 1 ₽)

- **Серьёзность:** высокая
- **Область:** ввод
- **Сценарий тест-плана:** APP-009, `test-areas/fees.md` (граничные значения в
  деньгах)

## Шаги воспроизведения

1. Открыть `app/index.html`, нажать «Сбросить данные».
2. Получатель: `T`. В поле «Сумма» ввести `1 000` (тысяча, с пробелом между
   разрядами).
3. Посмотреть превью «К списанию», нажать «Перевести», открыть
   `localStorage['payments-cabinet-v1']`.
4. Повторить с вводом `1,000` и `1.234,56`.

## Ожидаемый результат

Либо сумма распознаётся с учётом разделителя разрядов (`1 000` = 1000.00), либо
ввод отклоняется с понятным сообщением о формате. Пользователь не должен молча
отправить `1 ₽` вместо `1000 ₽`.

## Фактический результат

Сообщения об ошибке нет, перевод создаётся на усечённую сумму:

| Ввод | Сохранённая сумма |
| --- | --- |
| `1 000` | `1` |
| `1,000` | `1` |
| `1.234,56` | `1.234` |
| `100abc` | `100` |
| `1.2.3` | `1.2` |

## Доказательство

Браузерный прогон, `operations[0].amount` после каждого перевода — значения из
таблицы выше. Превью «Комиссия / К списанию» для `1 000` показывало
`10.00 ₽ / 11.00 ₽`, поле ошибки пустое.

Код `app/index.html`:

```js
function parseAmount(value) {
  return parseFloat(String(value).replace(",", "."));
  // "1 000"   -> parseFloat("1 000")   -> 1
  // "1,000"   -> "1.000" -> 1
  // "1.234,56"-> "1.234.56" -> 1.234
  // "100abc"  -> 100
}
// проверяется только isFinite(amount) && amount > 0 — обрезанное значение
// проходит проверку
```

## Предлагаемое направление фикса

Отклонять ввод, который после нормализации не является корректным
десятичным числом целиком (regex-валидация всей строки), либо явно
поддержать пробел/неразрывный пробел как разделитель разрядов и одну запятую
как десятичный разделитель. Допустимые форматы записать в `app/build-brief.md`.

## Исправлено

- **Сессия:** `sessions/2026-08-29-fix-bug-02-03-04.md`.
- **Решение:** строгий отказ (не поддержка пробела). В платёжном виджете
  молчаливое усечение суммы опаснее явной ошибки — списание необратимо,
  отказ нет; `1.234,56` к тому же читается двояко. Допустимый формат:
  целое, опционально одна точка **или** запятая и 1–2 знака после.
  Записан в `app/build-brief.md` (раздел «Фиксы 2026-08-29») и в
  `test-areas/fees.md`.

Изменения в `app/index.html`:

```js
// было
function parseAmount(value) {
  return parseFloat(String(value).replace(",", "."));
}
// стало
var AMOUNT_RE = /^-?\d+([.,]\d{1,2})?$/;
function parseAmount(value) {
  var s = String(value).trim();
  if (!AMOUNT_RE.test(s)) return NaN;
  return parseFloat(s.replace(",", "."));
}
```

В `doTransfer()` — отдельная проверка формата до проверки «больше нуля», с
сообщением «Сумма указана в неверном формате. Введите число без пробелов и
разделителей разрядов, например 1000 или 1000.50.». Пустой ввод по-прежнему
даёт «Сумма должна быть больше нуля» (сообщение APP-005 не изменилось); знак
минуса в регулярке сохранён, поэтому `-5` тоже даёт «больше нуля», а не
«неверный формат».

**Взаимодействие с BUG-01.** Грамматика (не более 2 знаков после разделителя)
закрывает дыру из раздела «Задело» BUG-01: сумма, прошедшая валидацию,
физически не может иметь >2 знаков — доли копейки из поля «Сумма» больше не
просачиваются в `round2(balance)`.
