# BUG-01 — Комиссия не округляется: в баланс уходят доли копейки, показанное ≠ списанному

- **Серьёзность:** высокая
- **Область:** комиссии
- **Сценарий тест-плана:** APP-003, `test-areas/fees.md` (открытый вопрос по округлению), FEE-017…024

## Шаги воспроизведения

1. Открыть `http://localhost:8765/app/index.html`, нажать «Сбросить данные».
2. Получатель: `Раунд Тест`. Сумма: `1234.56`.
3. Посмотреть строку «Комиссия» и «К списанию» под формой.
4. Нажать «Перевести».
5. Открыть DevTools → Application → Local Storage → ключ `payments-cabinet-v1`.

## Ожидаемый результат

Комиссия (1% от 1234.56 = 12.3456) округляется до двух знаков по заявленному
правилу. И на экране, и в истории, и в балансе используется одно и то же
округлённое значение. Баланс — денежная величина с двумя знаками после запятой.

## Фактический результат

- Превью: комиссия `12.35 ₽`, к списанию `1246.91 ₽`.
- В истории комиссия показана как `12.35`.
- В `localStorage` сохранено:
  - `operations[0].fee = 12.3456` — нескруглённая комиссия;
  - `balance = 48753.0944` — в балансе доли копейки.
- Экран показывает баланс `48753.09 ₽`, фактически в состоянии `48753.0944`.
- Реально списано `1234.56 + 12.3456 = 1246.9056`, то есть на `0.0044` больше,
  чем показанные пользователю `1246.91`.

При серии переводов ошибка накапливается, а баланс на экране расходится с
хранимым.

## Доказательство

Дамп `localStorage` сразу после шага 4 (браузерный прогон):

```json
{
  "balance": 48753.0944,
  "operations": [
    { "recipient": "Раунд Тест", "amount": 1234.56, "fee": 12.3456,
      "status": "done" }
  ]
}
```

Код `app/index.html`:

```js
function calcFee(amount) {
  var fee = amount * FEE_RATE;      // 1234.56 * 0.01 = 12.3456, округления нет
  if (fee < FEE_MIN) fee = FEE_MIN;
  if (fee > FEE_MAX) fee = FEE_MAX;
  return fee;
}
// ...
state.balance = state.balance - amount - fee;   // вычитается нескруглённое fee
```

## Предлагаемое направление фикса

Округлять комиссию до 2 знаков сразу после расчёта (до клиппинга или после —
зафиксировать правилом), например `fee = Math.round(amount * FEE_RATE * 100) / 100`,
и хранить баланс тоже округлённым. Правило округления записать в `app/build-brief.md`
и в `test-areas/fees.md`.

## Исправлено

- **Сессия:** `sessions/2026-08-28-fix-bug-01.md` (отдельная сессия «фикс»).
- **Правило:** HALF_UP до 2 знаков, зафиксировано в `app/build-brief.md`
  (раздел «Правило округления») и в `test-areas/fees.md` (открытый вопрос №2).

Изменения в `app/index.html`:

```js
// новый helper
function round2(n) {
  return Math.round((n + Number.EPSILON) * 100) / 100;
}

// процент округляется до клиппинга
function calcFee(amount) {
  var fee = round2(amount * FEE_RATE);
  if (fee < FEE_MIN) fee = FEE_MIN;
  if (fee > FEE_MAX) fee = FEE_MAX;
  return fee;
}

// баланс округляется после арифметики
state.balance = round2(state.balance - amount - fee);          // doTransfer
state.balance = round2(state.balance + op.amount + op.fee);    // cancelOperation
```

**Проверка (браузерный прогон, `sessions/2026-08-28-fix-bug-01.md`):**
после перевода `1234.56` в `localStorage` — `operations[0].fee = 12.35`,
`balance = 48753.09`; на экране `48753.09 ₽`. Показанное = списанному = хранимому.
APP-003 в `test-areas/app.md` и красный тест `APP-003 [BUG-01]` в
`tests/payments.spec.js` — зелёные. Регрессия по APP-001/002/004/010/011/012
не выявлена.

**Задело:** `round2` на балансе теперь поглощает и доли копейки, пришедшие из
самого поля «Сумма» (не только из комиссии). Пока сумма с >2 знаками принимается
без нормализации (BUG-03, вне этой сессии), баланс и сохранённое `amount` могут
разойтись в 3-м знаке. Отдельным дефектом не заводится — тянется за BUG-03.
