# BUG-02 — Дневной лимит привязан к дате по UTC, а не к местной дате

- **Серьёзность:** высокая
- **Область:** лимиты
- **Сценарий тест-плана:** APP-008, `test-areas/transfers.md` (открытый вопрос по
  часовому поясу суток), TR-032, TR-033

## Шаги воспроизведения

1. Машина в часовом поясе UTC+3 (Москва). Локальное время — между 00:00 и 03:00.
2. Открыть `app/index.html`, нажать «Сбросить данные».
3. Сделать перевод на 60 000 ₽ (в пределах дневного лимита 100 000 ₽).
4. Посмотреть строку «Дневной лимит: остаток …» и `operations[0].day` в
   `localStorage`.

## Ожидаемый результат

«Сегодня» для дневного лимита определяется по местному времени пользователя.
Счётчик расхода обнуляется в местную полночь. Перевод, сделанный в 00:30 по
местному времени, относится к новым суткам.

## Фактический результат

`todayKey()` возвращает дату по **UTC**. В UTC+3 с 00:00 до 03:00 местного
времени это ещё вчерашняя дата. Поэтому:

- переводы, сделанные ночью по местному времени, попадают во «вчерашний» бюджет
  лимита и суммируются с тем, что уже потрачено накануне — лимит может
  сработать там, где по местным суткам он ещё не исчерпан;
- фактическое обнуление счётчика происходит в 03:00 местного времени, а не в
  полночь;
- строка «остаток … из 100 000.00 ₽» показывает бюджет не тех суток, которые
  видит пользователь.

## Доказательство

```
new Date().getTimezoneOffset() === -180      // UTC+3, машина в Москве
new Date().toISOString().slice(0,10)         // "2026-08-28" — дата по UTC
```

Код `app/index.html`:

```js
function todayKey() {
  return new Date().toISOString().slice(0, 10);   // toISOString() — всегда UTC
}
function spentToday() {
  // суммирует op.amount только там, где op.day === todayKey()
}
// при переводе: operations.push({ ..., day: todayKey() })
```

Демонстрация механизма (браузерный прогон): операция на 99 000 ₽, сохранённая с
`day = "2026-08-29"` (завтра по UTC), **не учитывается** в дневном счётчике,
потому что `todayKey()` возвращает `"2026-08-28"`. То есть привязка идёт строго к
строке UTC-даты, локальная дата не участвует.

## Предлагаемое направление фикса

Формировать ключ дня по местному времени, например из `getFullYear` /
`getMonth` / `getDate`, и зафиксировать в `app/build-brief.md`, по какому
часовому поясу считаются сутки лимита.
