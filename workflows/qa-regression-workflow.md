# Workflow: регрессия платёжных проверок

Повторяемая процедура на случай, когда в тест-плане что-то поменялось (добавился
сценарий, изменилось граничное значение) и проверки нужно прогнать заново.

## Шаги

1. **Взять изменения.** Сравнить текущий `test-plan.md` с предыдущей версией
   (по git-истории) — какие пункты добавлены или изменены.
2. **Собрать список затронутых сценариев.** Не весь тест-план — только то, что
   реально поменялось плюс соседние пункты, которые могут быть задеты.
3. **Прогнать.** Пройти по списку затронутых сценариев, зафиксировать результат по
   каждому: прошёл / не прошёл / нужно уточнение.
4. **Проверка полноты — отдельным агентом.** Агент, не участвовавший в составлении
   списка на шаге 2, проверяет: не пропущен ли сценарий, который должен был
   попасть в список затронутых.
5. **Отчёт отдельным файлом.** Результат прогона — в `sessions/<дата>-regression.md`:
   что проверено, что не прошло, что осталось непроверенным и почему.

## Промпт для запуска

```
Мы прогоняем регрессию по workflow qa-regression-workflow.md.
1. Сравни текущий test-plan.md с последней версией в git-истории — что изменилось.
2. Собери список затронутых сценариев (изменённые + соседние, которые может задеть).
3. Пройди по списку, для каждого пункта запиши: прошёл / не прошёл / нужно уточнение.
4. Как закончишь — не проверяй сам себя. Я запущу отдельного агента на шаг 5.
```

Отдельным вызовом — проверка полноты:

```
Ты не участвовал в составлении списка затронутых сценариев для этого прогона.
Проверь: не пропущен ли сценарий, который должен был туда попасть, глядя на diff
test-plan.md. Список того, что упущено — отдельным разделом.
```

## Требования

- Каждый шаг оставляет файл, по которому видно, что он выполнен.
- Проверку выполняет агент, не участвовавший в предыдущем шаге.
- В конце — честный отчёт: что сделано, что не получилось, что осталось непроверенным.

## Статус

Записан, ещё не прогонялся на реальном изменении. Первый прогон — после того как
сводный `test-plan.md` будет собран из трёх областей.
